# 코드 컨벤션 기본값

새 프로젝트의 기본 스타일 방향은 Google Style Guides다. 이 참고 문서는 컨벤션 작성·수정 때만 읽는다. CONVENTIONS에는 해당 언어의 기준 가이드, 도구 설정 기준·검사 범위·명령, 테스트 판정 기준, 도구가 검사하지 않는 필수 규칙, 프로젝트별 예외를 담는다. 표준 가이드 전체의 준수를 모델의 기억이나 한 줄 지시로 보장하지 않는다.

| 언어 | 기본 가이드 |
|---|---|
| TypeScript | https://google.github.io/styleguide/tsguide.html |
| JavaScript | https://google.github.io/styleguide/jsguide.html |
| Python | https://google.github.io/styleguide/pyguide.html |
| Java | https://google.github.io/styleguide/javaguide.html |
| C++ | https://google.github.io/styleguide/cppguide.html |
| HTML/CSS | https://google.github.io/styleguide/htmlcssguide.html |

기준을 선정·변경할 때만 해당 언어 가이드의 필요한 절을 확인한다. 다른 언어는 [Google Style Guides 인덱스](https://google.github.io/styleguide/)에서 해당 가이드를 찾는다. 가이드가 없으면 해당 언어 공식 스타일 가이드·포매터 관례를 대체 방향으로 명시한다. 스타일 가이드 때문에 언어·프레임워크·의존성을 바꾸지 않는다.

## 문서 작성 시 확정할 것

- **자동 검사 범위:** 프로젝트에 맞는 도구·프리셋·설정의 상대 경로와 포맷·린트·타입 검사 범위·시점·명령을 확정한다. 설정 파일 생성에 필요한 핵심 옵션은 명세하고 기존 설정에 상세 값이 있으면 파일을 참조한다. 도구는 가이드의 일부만 강제할 수 있으므로 전체 준수라고 표현하지 않는다.
- **로컬 필수 규칙:** 도구로 검사하지 못하지만 위반 시 구현 결과를 수정해야 하는 규칙만 적는다. 대상·적용 조건·해야 할 행동을 명시한다. 가이드 전체 요약은 생성하지 않고 아키텍처/API가 소유하는 규칙은 해당 절을 참조한다.
- **예외:** 프레임워크 필수 파일명, 기본 방향과 다른 포매터 설정 등 실제 차이에만 적용 범위·규칙·이유를 기록한다. 필수 규칙과 같은 내용을 두 번 쓰지 않는다.
- **작업 결과 보고:** 기존 설정·명령을 확인하되 파일 존재·설치 여부·미실행 상태는 최종 보고에만 둔다. CONVENTIONS에 준비 상태 열이나 “아래는 모두 후속 구현 계획이며 미실행이다” 같은 문구를 추가하지 않는다. 실제 미정은 결정이 필요한 항목과 영향만 기록한다. 이 스킬은 앱 도구 설치·설정/스크립트 생성·앱 테스트를 수행하지 않는다.
- **기준 출처:** 해당 언어 가이드의 링크와 고정 revision이 있으면 남긴다. 링크는 작성·변경 근거이며 구현 때마다 열어야 할 필수 문서가 아니다. 외부 가이드 변경을 자동 반영하지 않는다. 접근할 수 없는 규칙을 지어내지 않는다.
- **테스트 규칙:** [CONVENTIONS 템플릿의 테스트 판정 기준](../assets/templates/CONVENTIONS.md#테스트-판정-기준)을 반영한다. 기존 문서 갱신에서도 같은 기준이 이미 있으면 병합하고 별도 필수 규칙으로 반복하지 않는다.
- **소유 범위:** CONVENTIONS에는 반복 검사에 필요한 명령·탐색/분리 규칙·테스트 판정 기준·기술적 검사 조건을 둔다. 초기화 선택값·통신·실행·배포 구조는 ARCHITECTURE, 기대 동작·AC는 MVP, HTTP 오류·헤더는 OpenAPI가 소유한다. 설치·DB 준비·앱 실행 절차를 넣거나 다른 문서의 표·본문·완료 기준을 테스트 매핑으로 재작성하지 않는다.

## 구현 전달과 충돌 처리

- 확정 명세에 따른 코드 작성·수정·리뷰의 외부 스타일 가이드 읽기 제한은 AGENTS에만 명시하고 CONVENTIONS에는 기준 출처와 적용 규칙을 둔다. 해당 제한이 필요한 API/프레임워크 사용법 확인까지 막지 않도록 한다.
- 가이드의 새 해석이나 적용 결정이 필요하면 적용 대상과 빠진 규칙을 보고하고 컨벤션 수정에서 해당 절만 확인해 프로젝트 규칙/설정 기준을 갱신한다. 이 작업은 전체 PRD 읽기를 허용하지 않는다. 현재 코드 작업에 외부 가이드의 새 규칙을 조용히 추가하지 않는다.
- 프로젝트별 예외는 명시된 범위에서 우선한다. 자동 검사 대상은 확정된 설정, 나머지는 로컬 필수 규칙을 따른다. 충돌하면 어떤 계약을 바꿀지 해소한 뒤 일치시킨다.
- 기존 프로젝트의 명시적인 규칙과 설정은 보존한다. 변경은 요청된 범위에서만 계획한다. 기존 설정을 임의로 바꾸거나 가이드를 도입한다는 이유로 불필요한 도구를 추가하지 않는다.
- 구현 완료 시 지정된 검사를 실행하고 위반을 수정한 뒤 필요한 검사를 다시 실행한다. 검사 성공은 해당 검사 범위의 근거이며 가이드 전체 준수의 증명이 아니다.

이 문서는 Google 문서의 복제본이 아니라 프로젝트에서 적용할 기준과 변경 방법을 정하는 지침이다.
